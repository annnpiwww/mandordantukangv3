# 08 Design Research and Planning

## Product analysis (before any screen)
Product category and purpose · target users, experience level · industry and competitors · brand personality · primary workflows and priorities · platform and technical constraints · data that actually exists.

## Creative direction (pick one, keep it consistent)
| Direction | Traits | Fits |
|---|---|---|
| Minimalist | clean, spacious | productivity, SaaS |
| Modern corporate | professional, structured | enterprise |
| Premium | refined type, restrained detail | finance, luxury |
| Glassmorphism | translucent layers | selective dashboards only |
| Neumorphism | soft dimensional | rare, specialized |
| Editorial | type-driven, asymmetric | content, portfolios |
| Brutalist | bold type, strong contrast | creative |
| Material-inspired | familiar patterns | general apps |
| Data-driven | dense, structured | analytics, monitoring, operations |
| Soft modern | friendly shapes, subtle color | consumer |
Choose by usability and identity, not trend.

## Design plan (mandatory for new features/redesigns, before code)
A Product analysis (purpose, users, problems, functional + platform requirements).
B Creative direction (personality, references, palette with HEX, fonts and pairing, type scale, spacing/grid, component styling, light/dark strategy).
C UX architecture (navigation, screen hierarchy, user flows, primary/secondary actions, component selection, interaction states).
D Screen concepts (objective, main information, layout, primary CTA, secondary actions, empty/loading/error, responsive behavior).
E Validation before coding (direction fits product, palette harmonious, type readable, hierarchy clear, workflow efficient, components consistent, scales later). Show the user a rendered mockup and wait for review.

## Research methods
Personas, journey maps, user flows, information architecture, task analysis, heuristic evaluation, cognitive walkthrough, usability testing, accessibility audit, A/B testing. Never claim user testing that did not happen.

## Competitor and pattern analysis
Collect 3-5 real products solving the same job; note what they show first, how they handle empty/error, navigation model, density. Borrow patterns, not skins.

## References (learn from, never copy)

- Systems: Material Design, Apple HIG, Ant Design, IBM Carbon, Shopify Polaris, Atlassian.
- Accessibility: WCAG, W3C WAI, WebAIM.

If browsing is unavailable, use established principles and label unverified trends as such.

## Ambiguity
State assumptions explicitly; ask the user only questions that change correctness or scope.
